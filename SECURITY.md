# Security reports

Do not include tokens, private keys or customer messages in public issues. Report vulnerabilities through this repository's private security advisory feature. Include the affected revision, a minimal reproduction using synthetic data, and the expected authorization boundary.

Workspace roles are distinct from device read permissions. Revocation prevents future authorized delivery but cannot erase keys or content already downloaded by a recipient. The hosted pilot is intended for test numbers.

There are two hosted remote MCP connectors, and they differ in what they can open:

- The hosted metadata connector (`https://api.wappie.thehappie.co/mcp`, `packages/mcp-http/server.mjs`, and every self-hosted container) is issued a read-only, device-restricted API key with an expiry, never a service account or an archive private key, and cannot return message content.
- The attested reader (`https://mcp.wappie.thehappie.co/mcp`, `packages/mcp-http/enclave/`) runs in an AWS Nitro Enclave whose published image the console verifies before consent. A `content` connection there is given its own read-only service account whose device grants are sealed to a key generated inside the enclave, held only in its memory, and never sent to the archive server, so the reader can open message text, chat and contact names and filenames of the consented numbers. When the consent also includes attachments (a media connection), the reader opens their contents inside the enclave as well, parsing each file in a jailed process (plain-text files are only decoded, in the reader itself, with no parser), and sends the assistant text and re-encoded images; it never opens view-once media, audio or voice notes, attachments the archive has not downloaded, or keyless or unhashed media, except that a video's preview image, sealed in the message itself, is sent whatever the video's key, hash or download status (the video itself is never fetched). Text connections open no attachment contents. Revoking the connection, its expiry, or removing or disabling the service account or the person who consented removes the account and its grants in one transaction; the enclave drops the key within a minute. Revocation stops future reads; it cannot retract what the assistant already received. [Who can read what](docs/mcp.md#who-can-read-what) states what Wappie's operators, the enclave's parent host, whoever controls DNS and the AI provider can and cannot see; [docs/mcp-enclave.md](docs/mcp-enclave.md) is the contract.
- From reader 0.6.0 the attested reader admits any MCP client that identifies itself with a Client ID Metadata Document on its own https domain, in two trust tiers: clients Wappie has tested, pinned with their exact return addresses in the published image and never fetched, and every other client, which reads message text only after the person ticks a second, deliberate box and within a history window and daily reading limits, and never drafts or sends. The reader fetches those documents itself, over TLS it verifies, through an egress proxy on its parent that only passes bytes to public addresses on port 443, and the browser checks that every field the consent card shows is attested. A connection token made in the console serves tools without OAuth; the reader keeps only its hash. Every new connection raises a banner in the console and an e-mail whose only link revokes it ([docs/mcp-enclave.md §19](docs/mcp-enclave.md#19-any-mcp-client-060)).

In both, OAuth tokens are minted and verified by the reader process, not by the archive server. Report connector token, OAuth, consent, attestation, key-handling, scope-escalation, attachment-parser or jail-escape issues through the same private advisory channel; from reader 0.6.0, also client identification (Client ID Metadata Documents and dynamic registration), the document fetch and its egress proxy (requests reaching private or internal addresses), the trust tier and the reading limits, the console connection token, consent phishing and look-alike names on the consent card, and e-mails that pretend to come from Wappie about assistants. Include the connection id, never the token, the API key, the sealed bundle or any message or attachment content.
